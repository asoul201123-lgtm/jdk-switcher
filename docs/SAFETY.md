# 环境修改的边界与恢复策略

## 修改范围

只访问两个固定注册表位置中的 `JAVA_HOME` 和 `Path`：

- `HKEY_CURRENT_USER\Environment`
- `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Session Manager\Environment`

系统级切换仅在当前账户已存在用户 `JAVA_HOME` 时同步该用户值。原有 JDK 目录、其他变量与 Path 中无关条目均保留。每次修改都有完整预览，系统级写入需要管理员身份。

读取注册表时使用 `DoNotExpandEnvironmentNames`，保留 `%变量%`、空值、缺失状态与注册表值类型。已经存在的 `Path` 保留 `REG_SZ` 或 `REG_EXPAND_SZ`；新增 Path 使用 `REG_EXPAND_SZ`。不支持的注册表类型会导致操作停止，不尝试转换。

## 切换步骤

1. 静态检查 `release`、`java.exe`、`javac.exe` 的必要结构；不执行二进制文件。
2. 基于新读取的环境快照计算计划，检查 Path 搜索优先级、变量长度和修改范围。
3. 获取跨进程互斥锁，重新比较完整快照；预览过期则停止。
4. 检查所需权限、重新检查 JDK 与切换计划。
5. 在本地用户数据目录创建受 ACL 保护的备份，刷盘并回读校验。
6. 每次写入前比较状态，写入后立即回读；失败则倒序回滚已经尝试写入的值。
7. 广播 `WM_SETTINGCHANGE` 通知。通知失败只提示重新登录，不把已成功的持久化写入误报为回滚。

界面不会改写自身、IDE 或已打开终端的进程环境，也不会关闭任何进程。新进程仍可能从旧父进程继承环境；注销登录能重新构建账户环境。

## 并发和崩溃

互斥锁约束本工具的实例，无法锁住 Windows 环境编辑器或其他第三方程序。注册表的多个值没有共同的原子提交点，检查与写入之间仍可能发生竞争。检测到第三方改动时停止操作；回滚仅在当前值仍等于本次写入值时恢复，避免覆盖后来修改的值。

进程被强制结束或系统断电时不能执行异常处理，但操作前的备份已经持久化。恢复计划逐个比较实际变更过的值：当前值等于操作后值时还原，已经等于原值时跳过，出现其他值则拒绝恢复。这样可以处理只写入了部分值的情况。

备份不是加密文件或数字签名文件。ACL 用于减少其他普通账户读取或篡改的风险，同一用户及本机管理员仍可访问。恢复仅接受当前机器和当前 SID 的备份，并验证结构、固定键名、值类型及当前状态。请在界面核对完整恢复预览，不导入来历不明的文件。

## 识别和生效检查的限制

扫描只针对本地磁盘和有限的候选路径，不执行未知可执行程序，不保证自动发现所有发行版。PE 文件头检查不是完整二进制验证或可信来源认证。JDK 应由用户从可信发行方获取。

持久化 Path 的判断采用保守规则：系统 Path 先于用户 Path；系统变量可能先于用户变量展开，因此不会假定用户 `JAVA_HOME` 能重定向系统 Path。目标 JDK 之前存在无法解析的变量、相对路径或网络路径时拒绝确认生效。不会修改或移除 Oracle 的 Java shim 来强行解决优先级。

不覆盖 IDE/构建工具固定的 Java 配置、当前目录内的可执行文件、命令别名、终端启动脚本、应用执行别名等。切换只影响持久化配置。兼容性、发行版可信度以及项目是否支持相应 Java 版本仍需用户自行确认。

## 隐私

程序没有网络请求、更新检查、遥测或后台服务。备份中含本机环境、账户 SID 和机器标识，只存入本地应用数据目录，程序不会上传。发布使用文件白名单并扫描常见个人路径、秘密信息与本机标识，不能代替对将要提交的 Git diff 和截图的人工作最终检查。

## 单文件 EXE

EXE 是普通权限的 .NET Framework Windows 桌面程序。C# 宿主只加载编译时嵌入的界面和核心资源，通过 Windows PowerShell 5.1 引擎在当前 STA 线程运行；不下载组件、不读取外部业务脚本、不执行命令行传入的脚本，不解压临时脚本，也不改变任何范围的执行策略。仅接受 `--demo` 和 `--smoke-test` 两个只读检查相关参数。

系统级切换的“以管理员重新打开”会通过 Windows UAC 启动同一个 EXE，并在新窗口重新扫描及预览，不会自动重放未确认的写入。EXE 内的代码与仓库 PowerShell 源码一致，仍使用同一套备份、校验与回滚流程。构建不生成 PDB 调试文件；发布前同时检查源码和二进制中的个人路径与本机标识。

EXE 目前未签名，SmartScreen 可能提示未知发布者。SHA-256 用于核对文件一致性，不能认证发布者身份。企业的应用控制、反病毒与 PowerShell 引擎限制依然可能限制应用启动；工具不更改这些设置。
